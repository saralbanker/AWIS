# EXECUTION CARD M18-C3r2  (security fix-only revision of M18-C3r; 99f7b13 stays DONE)
DISPATCH: awis-builder · BRANCH: m18-hardening-release
REVISION REASON (CE, 2026-10-11; background commit security review of 99f7b13, CE-confirmed):
`.github/workflows/release.yml` grants `contents: write` at workflow level and runs
`actions/checkout@v4` with default `persist-credentials: true`, so the write-scoped
GITHUB_TOKEN is stored in `.git/config` and readable by every step after checkout — including
`make verify` (all Go tests, Python plugin subprocesses, `go install` of third-party tools).
The file's comment "nothing before it can read it" is false. Additionally `setup-go`
`cache: true` in a publishing job restores a cache that ordinary branch-push runs can write
(cache poisoning into release binaries). This is a confirmed release-blocking security defect.

OBJECTIVE: Restructure release.yml into two jobs, same trigger (`push: tags: ["v*"]` only):
(1) `verify` — `permissions: contents: read`; checkout with `fetch-depth: 0` and
`persist-credentials: false`; setup-go "1.26.x" (cache allowed here — this job publishes
nothing); install golangci-lint v2.12.2; `make verify`. (2) `release` — `needs: verify`;
`permissions: contents: write` (job-level only; set workflow-level `permissions: {}` or
`contents: read`); checkout with `fetch-depth: 0` and `persist-credentials: false`; setup-go
"1.26.x" with `cache: false`; run ONLY `go run github.com/goreleaser/goreleaser/v2@v2.17.0
release --clean` with `GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}` in that step's env only. No
other steps in `release`. Fix the comments so every security claim in the file is true.
Lint the workflow with actionlint run via `go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.7`
(or the newest version that needs no Go toolchain newer than go.mod's) — report its output.
INPUTS: .github/workflows/release.yml; .github/workflows/ci.yml (pins to mirror); Makefile
(GORELEASER_VERSION).
ACCEPTANCE: actionlint clean on release.yml and ci.yml (report verbatim; if it flags a
pre-existing ci.yml issue, report it but do not modify ci.yml); release.yml has no step with
access to a write token except the goreleaser step; `persist-credentials: false` on both
checkouts; no cache in the release job; `make gofmt-check vet build lint` green; no tag
created, nothing pushed, no GITHUB_TOKEN used locally; no other file changed. COMMIT once.
REPORT ≤200 tokens plus the final release.yml verbatim and the actionlint output.
